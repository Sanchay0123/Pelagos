# Pelagos Operational Maritime Routing Foundation Implementation Plan (Milestone D9.4)

## 1. Scope and Explicit Non-Goals

### 1.1 Scope
This document defines the technical architecture, execution stages, validation criteria, and licensing guardrails for Milestone D9.4: **Production Routing Foundation**.

D9.4 transitions Pelagos from the synthetic corridor test fixture established in D9.2 ([`1780234`](file:///c:/Users/Lenovo/Desktop/random%20codes/SIH26/Pelagos)) to an operational routing engine powered by a verified, real-world navigable shipping network derived from upstream Eurostat SeaRoute MARNET data, as investigated in D9.3 ([ROUT-002](./D9.3-real-network-data-investigation.md)).

The milestone encompasses:
1. **Reproducible Local Acquisition Pipeline**: Secure, non-interactive retrieval and SHA-256 verification of pinned upstream GeoPackage assets into a dedicated, Git-ignored local cache.
2. **Deterministic Graph Ingestion Pipeline**: Offline parsing, self-loop removal, parallel-edge aggregation, geodesic edge weighting, and antimeridian connector generation.
3. **Dual-Mode Service Layer Integration**: Runtime configuration enabling isolated prototype execution for unit tests alongside operational MARNET graph routing, with fail-closed missing-cache behavior and strict prohibition against misrepresenting synthetic routes as operational.
4. **Antimeridian-Safe Geometry Serialization & Rendering**: RFC 7946-compliant antimeridian cutting and polyline segmentation to eliminate cross-globe rendering artifacts in both 3D CesiumJS and 2D planar map projections.
5. **Comprehensive Test Suite**: Automated verification covering checksum enforcement, schema validation, regression counts, port snapping limits, canal/polar policies, and end-to-end corridor routing.

### 1.2 Explicit Non-Goals
To protect project stability and maintain honest navigation claims:
- **No Certified Electronic Navigation (ECDIS)**: Pelagos calculates macro-level commercial shipping routes and voyage metrics. It does not provide hydrographic chart navigation, real-time collision avoidance, shallow-water sounding clearances, or bridge-level passage planning.
- **No Commitment of MARNET Assets to Git**: In accordance with the D9.3 licensing evaluation, no raw GeoPackages or derived JSON/Parquet network assets will be committed to the Git repository while upstream source rights remain unresolved.
- **No Automatic Straight-Line Fallbacks**: The engine will strictly enforce [REQ-FR-OMR-002](../requirements/functional-requirements.md); any query between disconnected points or exceeding snapping thresholds will return an explicit `unsupported_route` status with empty geometry.
- **No Dynamic Weather or Metocean Routing in D9.4**: Dynamic wave drift, tidal stream current integration, and tropical cyclone evasion ([REQ-FR-OMR-004](../requirements/functional-requirements.md)) remain scheduled for Milestone D10+.
- **No Modification of Core Persistence Stores**: The operational SQLite store (`pelagos.db`), backup databases (`pelagos.db.bak`), and analytical Parquet partitions (`parquet_data/`) will not be altered or migrated.

- Metadata is written to `.cache/pelagos/routing/manifest.json` recording source URL, commit SHA, file size, SHA-256 hash, ingestion timestamp, parser version, and EUPL-1.2 license declaration.

### Workstream 2 — Deterministic Graph Ingestion

#### GeoPackage & WKB Parsing Specification
To eliminate native C++ compilation dependencies (`gdal`, `geopandas`, `fiona`) and maintain complete compliance with [REQ-NFR-DCT-001](../requirements/nonfunctional-requirements.md), graph construction will use Python's standard library `sqlite3` and `struct` modules:

1. **OGC GeoPackage Binary Header Parsing**:
   - Validates the standard 2-byte magic identifier `0x4750` ("GP") at byte offset 0.
   - Extracts flags from byte 3:
     - Endianness (bit 0): `0` = Big-Endian (`>`), `1` = Little-Endian (`<`).
     - Envelope indicator (bits 1–3): `0` = no envelope (header size 8 bytes), `1` = 2D envelope (40 bytes), `2`/`3` = 3D/measured envelope (56 bytes), `4` = 4D envelope (72 bytes).
   - Validates Spatial Reference System ID (SRID) = `4326` at byte offset 4.
2. **WKB LineString Parsing**:
   - Parses the standard ISO/OGC Well-Known Binary body following the header offset.
   - Asserts geometry type code = `2` (`wkbLineString`).
   - Unpacks point count $N$ as an unsigned 32-bit integer.
   - Unpacks $N$ pairs of 64-bit IEEE 754 floating-point coordinates $(X, Y)$ representing $[longitude, latitude]$.
   - Validates bounds: $-180.0 \le X \le 180.0$, $-90.0 \le Y \le 90.0$, and asserts non-NaN, non-infinite coordinates.

#### Graph Construction Rules
- **Vertex Identity & Hashing**: Nodes are defined by coordinate tuples `(round(lon, 6), round(lat, 6))`, providing millimeter-level topological precision and preventing floating-point hashing divergence across OS platforms.
- **Self-Loop Exclusion**: If $u == v$ (start coordinate equals terminal coordinate), the feature is discarded. The D9.3 audit established exactly 20 self-loops in the 50 km dataset, none of which carry chokepoint tags, and all of which connect to valid non-loop edges. Discarding them prevents useless 0-hop cycles in Dijkstra pathfinding.
- **Parallel-Edge Aggregation**: If multiple LineString features connect the same endpoints $\{u, v\}$, the pipeline:
  - Asserts passage attribute consistency across features (D9.3 verified 0 passage attribute conflicts across all 67 parallel groups).
  - Retains the edge with the shortest WGS 84 geodesic length, discarding 67 redundant parallel tracks.
- **Geodesic Edge Weighting**:
  Edge distance is calculated as the sum of geodesic segment distances along all internal vertices via `pyproj.Geod(ellps='WGS84')`:
  $$W = \sum_{i=0}^{k-1} d_{geodesic}(P_i, P_{i+1}) \quad \text{converted from meters to NM via } 1,852\text{ m/NM}$$
- **Antimeridian Connector Generation**:
  - Boundary nodes are identified where $|lon - 180.0| < 10^{-5}$ or $|lon - (-180.0)| < 10^{-5}$.
  - Connectors are generated if and only if $|lat_1 - lat_2| < 10^{-5}$ (exact latitudinal parity).
  - Connector weight is set to **$0.0\text{ NM}$** (physically exact, since $+180.0^\circ$ and $-180.0^\circ$ represent identical coordinates on Earth).
  - Exactly 12 antimeridian bridge edges are inserted with attributes `stitched=True, pass_id=None`. Cross-latitude diagonal connectors are strictly prohibited.
- **Regression Expectations vs. Future Flexibility**:
  - The pipeline checks the output against the inspected revision counts: **7,390 nodes** and **15,423 edges**.
  - These values are treated as **regression expectations for commit `88a2e568`**, with clear diagnostic warnings if an alternate source file is processed.

### Workstream 3 — Routing Service Integration

#### Dual-Mode Engine Architecture
`MaritimeRoutingEngine` in [`backend/pelagos/routing/service.py`](file:///c:/Users/Lenovo/Desktop/random%20codes/SIH26/Pelagos/backend/pelagos/routing/service.py) will support explicit dual-mode operation:

```python
class MaritimeRoutingEngine:

        self,
        mode: str = "prototype",  # "prototype" | "operational"
        cache_dir: Optional[Path] = None,
        fixture_path: Optional[Path] = None,
    ) -> None:
        ...
```

1. **Configuration**:
   - Controlled by the environment variable `PELAGOS_ROUTING_MODE` (`prototype` vs. `operational`, defaulting to `prototype` in local development and CI).
   - Can be overridden via constructor arguments in test suites.
2. **Fail-Closed Missing Cache Behavior**:
   - If `mode="operational"` and the processed network cache (`.cache/pelagos/routing/marnet_network.json`) is missing or invalid:
     - **The engine will NEVER silently fallback to the prototype fixture and label the route operational.**
     - The engine raises a descriptive initialization error or returns `status="service_unavailable"` with explicit instructions to run `python scripts/ingest_marnet.py`.
3. **Port Snapping Limits**:
   - Origin and destination coordinates are snapped to the nearest graph node via WGS 84 geodesic distance.
   - Snapping distance threshold is enforced at **50.0 NM**.
   - If the nearest graph node exceeds 50.0 NM, the request fails with `status="invalid_input"` or `status="unsupported_route"`: `"Origin coordinate [-104.99, 39.73] is 712.4 NM from navigable shipping lanes, exceeding the 50.0 NM snapping limit."`
   - The connector distance from port gate to the graph node is tracked and included in the response summary (`connector_distance_nm`).
4. **Canal and Polar Passage Constraints**:
   - `canal_policy="allow"`: standard routing through Panama and Suez.
   - `canal_policy="avoid_panama"`: edge weight for `panama` edges set to $\infty$, routing vessels via Cape of Good Hope or Suez.
   - `canal_policy="avoid_suez"`: edge weight for `suez` edges set to $\infty$.
   - **Default Polar Masking**: Edges tagged `northwest` or `northeast` are assigned infinite weight ($10^9$) by default, preventing non-ice-class vessels from routing through Arctic passages.
5. **Route Provenance & Metadata**:
   - Operational responses return `route_method="marnet_shipping_lane_network"`.
   - Prototype responses return `route_method="prototype_test_network_graph"` with mandatory test-fixture warnings.
   - All responses include full provenance dictionaries and ECDIS safety disclaimers.

### Workstream 4 — Antimeridian-Safe Route Geometry

#### Visual Artifact Problem Analysis
In GIS systems and rendering engines, a line connecting a point at $+180.0^\circ$ longitude to $-180.0^\circ$ longitude creates a planar discontinuity:
- In 2D map views (Leaflet, OpenLayers, Mapbox, and Cesium 2D/Columbus View), drawing a line from $x = +180$ to $x = -180$ draws a continuous line across the entire screen ($360^\circ$ longitudinal span).
- In CesiumJS 3D mode (`SceneMode.SCENE3D`), `Cartesian3.fromDegrees(180, lat)` and `Cartesian3.fromDegrees(-180, lat)` resolve to the exact same $(X, Y, Z)$ coordinate. However, when ground clamping (`clampToGround: true`) is enabled, Cesium's surface interpolator subdivides lines based on spherical angles. If $|\Delta lon| \approx 360^\circ$, it can wrap along the equator.

#### Normalization Strategy: Dual-Field API Contract
To guarantee backward compatibility with clients consuming the current flat coordinate array while providing standard GeoJSON antimeridian rendering:

1. **`geometry` Field (Backward Compatible)**:
   - Remains `List[List[float]]` containing the ordered sequence of `[longitude, latitude]` pairs.
2. **`geometry_segments` Field (RFC 7946 Antimeridian Cut)**:
   - Type: `List[List[List[float]]]`.
   - Whenever an antimeridian bridge edge is traversed, the route is cut at the 180th meridian into disjoint segments:
     - Segment 1: Origin to $-180.0^\circ$ (e.g., Seattle to Date Line: `[[-124.75, 48.5], ..., [-180.0, 40.0]]`).
     - Segment 2: $+180.0^\circ$ to Destination (e.g., Date Line to Yokohama: `[[180.0, 40.0], ..., [139.73, 35.15]]`).
   - If a route crosses the Date Line multiple times, a new segment is created at each crossing.
3. **`geojson` Field (Standard GeoJSON Feature)**:
   - Emits a GeoJSON Feature where geometry is a `LineString` for non-crossing routes, or a `MultiLineString` for antimeridian-crossing routes.
4. **Distance Conservation**:
   - Geodesic distance calculation is strictly preserved because the bridging segment has a weight of $0.0\text{ NM}$, and leg distances are evaluated segment-by-segment.
5. **Frontend CesiumJS Adaptation ([`gods-eye-view-main/src/layers/directions/index.js`](file:///c:/Users/Lenovo/Desktop/random%20codes/SIH26/Pelagos/gods-eye-view-main/src/layers/directions/index.js))**:
   - Update `drawRoute(route)` to check for `route.geometry_segments`:
     ```javascript
     const segments = route.geometry_segments || [route.geometry];
     for (let i = 0; i < segments.length; i++) {
       const positions = Cesium.Cartesian3.fromDegreesArray(segments[i].flat());
       _viewer.entities.add({
         id: `directions:route:segment:${i}`,
         polyline: {
           positions,
           width: 9,
           material: new services.annotations.FlowMaterialProperty(DIRECTIONS_ROUTE_COLOR),
           clampToGround: true,
           classificationType: Cesium.ClassificationType.BOTH,
         },
       });
     }
     ```
   - This renders each segment as an independent ground-clamped entity, eliminating cross-world lines in all viewing modes.

### Workstream 6 — Dependencies, Performance, and Operations

#### Dependency Justification
- **Zero New External Dependencies**: The entire ingestion pipeline and graph engine will use packages already present in the Pelagos environment:
  - Python standard library: `sqlite3`, `struct`, `hashlib`, `urllib.request`, `json`, `pathlib`.
  - Installed libraries: `networkx` (3.3), `pyproj` (3.6.1), `pydantic` (2.x).
  - Heavy GIS C++ packages (`gdal`, `geopandas`, `fiona`, `shapely`) are strictly excluded.

#### Performance and Resource Benchmarks
Based on empirical profiling conducted during D9.3:
- **Offline Ingestion Runtime**: ~2.5 to 3.5 seconds to parse GeoPackage blobs, compute geodesic lengths, stitch antimeridian edges, and serialize JSON.
- **Cache File Size**:
  - Raw GeoPackage: 1.55 MB (`marnet_plus_50km.gpkg`).
  - Serialized Network JSON (`marnet_network.json`): ~3.8 MB uncompressed (~1.1 MB gzipped).
- **Service Cold Startup**: ~35 to 50 ms to parse JSON and populate NetworkX graph structures in memory.
- **Runtime Memory Overhead**: ~14 to 18 MB in RAM for the full 7,390-node / 15,423-edge graph.
- **Pathfinding Query Latency**: ~15 to 35 ms for standard Dijkstra shortest path across 7,390 nodes.

#### Security Considerations
- TLS certificate verification is enforced on all downloads.
- Path traversal protections: target download paths are constrained strictly within `.cache/pelagos/routing/`.
- Safe SQLite queries: all SQL statements use static parameterized queries; zero string formatting.
- Checksum verification occurs before opening or executing any SQLite operations on the downloaded file.

## 8. Risks, Unresolved Decisions, and Rollback Strategy

### 8.1 Technical and Operational Risks
| Risk | Severity | Mitigation Strategy |
|---|---|---|
| **Upstream URL Disruption / Deletion** | Medium | Assets are pinned to an immutable Git commit hash (`88a2e568`). Local cache ensures offline reproducibility once downloaded. |
| **Antimeridian Rendering Artifacts** | High | Dual-field API contract (`geometry` + `geometry_segments`) separates display segmentation from total distance summation. |
| **Excessive Port Snapping Distance** | High | Strict 50.0 NM ceiling enforced; connector distance included in metrics; disconnected ports return explicit error. |
| **Accidental Repository Bloat** | High | `.gitignore` explicitly excludes `.cache/` and `data/`; pre-commit hooks verify no `.gpkg` or large `.json` files are staged. |
| **Silent Prototype Fallback** | Critical | Service layer refuses to fall back silently in operational mode; returns `service_unavailable` if cache is absent. |

### 8.2 Rollback Strategy
Because D9.4 introduces the operational engine alongside the existing prototype fixture without altering database tables or existing APIs:
1. If the operational MARNET cache proves unstable or corrupt, setting `PELAGOS_ROUTING_MODE=prototype` immediately restores the proven D9.2 prototype engine.
2. The prototype fixture (`fixtures/sea_lanes.json`) remains completely unmodified and frozen as the default test harness.
3. Deleting `.cache/pelagos/routing/` completely removes all external data assets without leaving orphaned dependencies or modified Git files.
